# threepass

**An AI code reviewer that publishes its own numbers.**

`threepass` reviews a diff with three independent passes (correctness, security and data safety, and architecture), reconciles what they find into one ranked comment, and never spends more than a set amount per review. It ships with an eval set of real and planted bugs, and reports recall, precision and cost per pass. You can rerun the eval yourself.

> **Status: early.** The design and eval plan are written; the code is being built ([roadmap](docs/roadmap.md)). The results table below fills in automatically from the first labeled eval run. Until then, there are no numbers to claim.

## Why three independent passes

Most multi-step reviewers chain their steps: each one sees what the previous one found. That's efficient, but a reviewer shown a list of findings tends to work on that list instead of looking at the code fresh. One early miss becomes everyone's miss.

`threepass` does the opposite:

- **Each pass gets the same frozen input** and has one job. No pass sees another's output, and a test enforces it.
- **A deterministic reconciler** merges duplicates and ranks the findings.
- **Agreement counts.** When two passes independently flag the same lines, confidence goes up.

That's a claim, so the eval tests it. It runs the same dataset four ways:

- independent passes,
- chained passes,
- one combined pass,
- the combined pass sampled three times, which is the cost-matched control.

The results get published whichever way they go. Reasoning in [ADR 0001](docs/decisions/0001-independent-passes.md).

## What each pass looks for

| Pass | Looks for |
|---|---|
| **Correctness** | Does the code do what the PR says? Edge cases, nil and empty handling, error paths, off-by-one errors, broken contracts, tests that don't test the change |
| **Security and data safety** | Injection (SQL, shell, path, template), missing authorization, IDOR, SSRF, secrets and PII in code or logs, unsafe deserialization, destructive operations without guards |
| **Architecture and conventions** | Fit with this codebase, judged against your `CLAUDE.md`, `AGENTS.md` or conventions file: layering, duplicated helpers, dead code, naming |

## Cost, answered up front

Three passes cost roughly three times the input tokens of one. So:

- **There's a hard ceiling.** `max_cost_usd` (default $0.50) is estimated before any call. If a review would go over, the tool trims context, then skips the architecture pass, then refuses. It never silently overspends.
- **Every review reports what it cost,** per pass, in the comment itself.
- **The eval reports cost per review** (median and p90) next to recall and precision.

## Usage

> Not on RubyGems yet. Run it from a clone with Ruby 3.3+.

```bash
bundle install
export ANTHROPIC_API_KEY=...

git diff main...HEAD > change.patch
bundle exec exe/threepass review --diff change.patch --repo . --title "Add sortable invoice columns" --body-file pr.md
```

`--diff -` reads the diff from stdin. `--format json` prints machine-readable output. `--fail-on high` exits 2 when a finding is at least that severe, and exit code 3 means the cost ceiling refused the review. `bundle exec exe/threepass --help` lists every flag.

To try it without an API key, replay the fixture responses:

```bash
THREEPASS_FAKE=test/fixtures/llm/basic bundle exec exe/threepass review \
  --diff test/fixtures/diffs/basic.patch --repo test/fixtures/repo --title "Add sortable invoices"
```

A GitHub Action that posts the comment on every push is designed ([design: GitHub Action](docs/design.md#github-action)) but on hold, so for now the CLI is the only interface.

The output is one comment. An illustrative example (not real output):

```markdown
### threepass: 2 findings (1 high)

| | Finding | Where | Passes | Confidence |
|---|---|---|---|---|
| high | User input interpolated into SQL | app/models/invoice.rb:42-47 | security, correctness | 0.94 |
| medium | Nil customer not handled in #total_due | app/models/invoice.rb:88 | correctness | 0.72 |

Cost $0.087 (correctness $0.031, security $0.029, architecture $0.027) · 3 findings below threshold
```

Configure it with `.threepass.yml`: model, cost ceiling, confidence threshold, conventions files and pricing. See [design: config](docs/design.md#config).

## Run the eval yourself

```bash
bundle install
bundle exec rake eval:validate
ANTHROPIC_API_KEY=... bundle exec rake "eval:run[independent]"
bundle exec rake eval:report
```

Precision is only printed after unmatched findings are labeled by a person (`evals/labels/`). Before that, the report shows "unverified findings per PR" instead. See [eval design: labeling](docs/eval-design.md#labeling-what-makes-precision-honest).
